## aicr 流程
- 定义了AlCR的提示词，存储到 AICR.md
- 用Git命令 `git diff master > mybranch.diff` 生成当前分支与 master 分支的 .diff 文件
- 使用 @xxx.md 对 diff 文件进行 CodeReView
- 分析报告中的Critical、Warning、Info问题，重点先解决 Critical 问题

## 提示词设计
1. 首先，我会先为AI设定定义一个角色，比如：作为Java资深架构师/技术专家进行代码评审

2. 其次，我设定代码评审中判定的问题划分为三类，分别是 Critical (必须修复)、Warning (建议修复)、Info (优化建议)，各自针对不同方面的问题，方便我们在开发时挑选优先级更高的优先进行修改
	+ Critical (必须修复) 包括：安全漏洞、严重性能问题、数据一致性问题、线程安全问题、空指针
	+ Warning (建议修复) 包括：代码质量问题、潜在性能隐患、可维护性问题
	+ Info (优化建议) 包括：代码风格改进
	
3. 接着，针对评审的方向，我会定义一些具体的评审内容
	+ 比如代码质量方向，具体就会包括注释清晰且必要、方法长度适中，单一职责原则、遵循命名规范等
	+ 比如安全性方向，具体就会包括日志记录不包含敏感信息、敏感数据加密等

4. 最后我会规范AI的输出结果，我会提供一个问题报告模板，让AI去照着模板输出内容

5. 模板内容就包括：问题类型是Critical还是Warning还是Info、影响是什么、建议是什么 这样的报告模板

## aicr 中你们认为哪些是 critical 的，必须要处理的？
Critical 主要包括：安全漏洞、严重性能问题、数据一致性问题、线程安全问题、空指针
我认为这些是必须处理的，而 Warning 和 Info 主要定义的是 可维护性、代码风格等问题
