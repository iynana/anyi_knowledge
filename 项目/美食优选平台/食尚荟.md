技术栈：SpringBoot+MySQL+Redis+Lua+Kafka+Caffeine+MybatisPlus 等
项目简介：美食优选平台为用户提供了商家信息查询、秒杀优惠券、笔记发布等功能，同时帮助商家推广优惠信息。
项目亮点：
- **秒杀设计**：使用 Redis 存储库存和订单信息， Lua 判断用户下单资格，保证库存不超卖和一人一单，同时使用消息队列异步处理数据库，解耦秒杀流程与数据持久化以提高并发度
- **缓存设计**：使用**逻辑过期**方案防止缓存击穿问题；使用**缓存空值**方案拦截无效查询；使用本地缓存和 Redis 缓存搭建**二级缓存**架构，提高热点数据访问速度
- **数据一致性**：利用Redis实现商户缓存，采用 **Cache Aside缓存更新** 策略，通过更新数据库后删除缓存+TTL 兜底保证数据一致性
- **系统限流**： 基于**滑动窗口**实现多维度限流，防止系统过载、刷券、爬虫

**最大挑战点**：
+ 最大技术挑战是**秒杀模块，在高并发下基于数据库做库存扣减，出现了数据库热点行锁竞争严重、响应慢。**
+ **原始方案**：
	+ 从Mysql获取商品信息，判断是否在秒杀时间
	+ 判断库存够不够
	+ 加上redisson锁（用户锁）
	+ 检查一人一单
	+ **乐观锁扣库存**，==mysql写热点行==
	+ 创建订单
+ **异步方案**：
	+ Redis 预扣减库存，将订单消息写入到消息队列，给用户返回下单中
	+ 后台线程检测消息队列，获取订单消息，完成下单
	+ 前端轮询，给用户返回信息失败or成功
	+ **最终一致性**：重试+死信队列+人工干预，幂等性保证，定时对账补偿
最终测试
+ 异步情况下：测试10000线程数，200个库存，平均响应时间18.3ms，吞吐量2000QPS，数据库落库67单/s
+ 同步情况下：测试10000线程数，200个库存，平均响应时间54.38ms，吞吐量750QPS，数据库落库40单/s
 相比之下，吞吐量是同步下的快3倍，平均响应时间降低2/3
