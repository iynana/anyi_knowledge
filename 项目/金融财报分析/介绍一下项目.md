这个项目最初的出发点是我在使用传统RAG时发现，它只能做**单次检索+生成**，在一些复杂问题下经常回答不完整。

主要包括两部分：
一部分是文件的上传解析向量化
一部分是问答流程

**文档的处理**：
1.上传文档
2.后端使用 mineru 把pdf解析成markdown
3.而后固定大小分块策略对长文本进行分块(embedding-text-v3)
4.向量化存储到postgresql中，并保留元数据

**问答的流程**：
1.用户输入query
2.初始化当前上下文 = 召回短期记忆（窗口+摘要）+ 重写的query（==从上下文约束，到实时依据，到当前问题==）（==从生成式ai看，prompt 必须“从抽象到具体”，因为前序 token 会定义后续 token 的语义空间\[Key/Value\]，而具体信息需要在这个空间中被解释和匹配，否则会导致语义建模失效或不稳定==）
3.利用重写的query召回长期记忆
3.advisor阶段：LLM提取已知信息，并根据目前信息缺口，生成下一轮query（没有信息缺口的话，可以直接整合最终答案）
4.executor阶段：使用混合检索，召回最相关的topk（包括工具调用结果）
5.observation阶段：对召回的chunk，进行关于用户query的摘要
6.继续进行推理-检索的循环，最多循环10次
