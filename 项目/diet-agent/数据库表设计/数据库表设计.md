## 1. 概述
饮食助手（diet-agent）使用 MySQL 8.0 作为持久化存储，Schema 名为 `diet_db`。DDL 脚本位于：
`src/main/resources/db/diet_db.sql`

### 1.1 设计原则

| 原则          | 说明                                                                                    |
| ----------- | ------------------------------------------------------------------------------------- |
| 无外键约束       | 表间通过 `session_id`、`user_id`、`trace_id` 等逻辑关联，DDL 中 `FOREIGN_KEY_CHECKS = 0`，便于独立迁移与清理 |
| JSON 承载可变结构 | 槽位、推荐历史、餐食标签、Trace 事件等半结构化数据使用 `json` 列，减少频繁改表                                        |
| 用户 ID 外置    | `user_id` 为业务侧传入的长整型，本库不维护用户表，鉴权由上层网关/业务系统负责                                          |
| 读写分离职责      | 会话状态由 Orchestrator 独占写入；消息、Trace、反馈为追加型写入；餐食与槽位字典为配置型数据                               |

### 1.2 表清单

| 表名                   | 中文名        | 核心职责                   |
| -------------------- | ---------- | ---------------------- |
| `diet_sessions`      | 会话状态表      | 多轮对话阶段、槽位、推荐历史         |
| `diet_messages`      | 对话消息表      | 用户/助手消息流水              |
| `diet_request_trace` | 请求 Trace 表 | Agent 链路追踪与人工标注        |
| `diet_slot_option`   | 槽位选项字典     | 7 维槽位合法取值              |
| `meal_item`          | 餐食条目表      | PUBLIC/PERSONAL 双数据源菜单 |
| `recommend_feedback` | 推荐反馈表      | 用户对推荐结果的采纳/评分          |

**关联说明：**
- 一个 `diet_sessions` 行对应一次完整多轮对话上下文。
- `diet_messages`、`diet_request_trace`、`recommend_feedback` 均通过 `session_id` 挂到同一会话；查询时额外带 `user_id` 做归属校验。
- `recommend_feedback.item_id` 可空，指向 `meal_item.id`，表示用户对某道具体餐食的反馈。
- `diet_slot_option` 与 `meal_item` 无直接外键，通过槽位名称与选项值在业务层对齐。

## 3. 表结构详述
### 3.1 diet_sessions — 会话状态表

存储 Orchestrator 维护的多轮对话状态，是推荐链路的「单一事实来源」。

| 字段                     | 类型            | 约束       | 说明                                       |
| ---------------------- | ------------- | -------- | ---------------------------------------- |
| `id`                   | `varchar(64)` | PK       | 会话 ID，格式 `sess_` + UUID（无连字符）            |
| `user_id`              | `bigint`      | NOT NULL | 所属用户，与请求 Header/参数一致                     |
| `phase`                | `varchar(64)` | NOT NULL | 会话阶段，枚举见下表                               |
| `slots`                | `json`        | NOT NULL | 7 维槽位 + `_meta` 元信息                      |
| `last_recommendations` | `json`        | NOT NULL | 本会话已推荐过的 `meal_item.id` 列表（累积，用于「换一批」去重） |
| `created_at`           | `datetime`    | NOT NULL | 创建时间                                     |
| `updated_at`           | `datetime`    | NOT NULL | 最后更新时间                                   |

**phase 枚举（**`SessionPhase`**）：**

| 值           | 含义              |
| ----------- | --------------- |
| `START`     | 会话刚创建，尚未进入业务流程  |
| `CLARIFY`   | 系统正在追问缺失槽位      |
| `RECOMMEND` | 已进入推荐链路并保存过上轮结果 |
| `PLAN`      | 正在处理多餐规划        |


**slots JSON 结构：**
```json
{
  "mealTime": ["午餐", "晚餐"],
  "mood": ["疲惫"],
  "scene": ["工作"],
  "healthGoal": ["清淡", "养胃"],
  "cuisine": ["家常"],
  "taste": ["清淡"],
  "convenience": ["快速", "一人食"],
  "_meta": {
    "sourceMode": "PUBLIC",
    "currentIntent": "MEAL_RECOMMENDATION"
  }
}
```

| JSON 路径                    | 类型         | 说明                                                |
| -------------------------- | ---------- | ------------------------------------------------- |
| `mealTime` ~ `convenience` | `string[]` | 对应 `SlotBundle` 七维槽位，值为 `diet_slot_option` 中的中文选项 |
| `_meta.sourceMode`         | `string`   | `PERSONAL` / `PUBLIC`，决定餐食检索数据源                   |
| `_meta.currentIntent`      | `string`   | 当前确认的意图，枚举见 `Intent`                              |

**读写方：**

- 写入：`SessionStateService`（Orchestrator 每轮结束 `save`）
- 读取：`SessionStateService.loadOrCreate`、`SessionMapper.findById`

### 3.2 diet_messages — 对话消息表

追加型消息流水，供 IntentAgent 短期上下文与前端历史展示。

| 字段               | 类型             | 约束                 | 说明                                 |
| ---------------- | -------------- | ------------------ | ---------------------------------- |
| `id`             | `bigint`       | PK, AUTO_INCREMENT | 自增主键                               |
| `session_id`     | `varchar(64)`  | NOT NULL           | 关联 `diet_sessions.id`              |
| `role`           | `varchar(32)`  | NOT NULL           | 消息角色：`user` / `assistant`          |
| `content`        | `text`         | NOT NULL           | 消息正文                               |
| `intent`         | `varchar(64)`  | NULL               | 该轮识别出的意图（`Intent` 枚举名），可为空         |
| `agent_trace_id` | `varchar(128)` | NULL               | 关联本轮 `diet_request_trace.trace_id` |
| `created_at`     | `datetime`     | NOT NULL           | 消息时间                               |

**读写方：**
- 写入：`SessionService.appendMessage`（每轮 user/assistant 各一条）
- 读取：`SessionService.recentConversationTurns`（默认最多 `diet.session.max-history-turns` 条，配置默认 10）

### 3.3 diet_request_trace — 请求 Trace 表

记录每轮 `/chat` 请求的完整 Agent 链路，支持调试、评估与人工标注。

| 字段                        | 类型             | 约束                  | 说明                          |
| ------------------------- | -------------- | ------------------- | --------------------------- |
| `id`                      | `bigint`       | PK, AUTO_INCREMENT  | 自增主键                        |
| `trace_id`                | `varchar(128)` | NOT NULL, UK        | 请求级唯一 Trace ID              |
| `session_id`              | `varchar(64)`  | NOT NULL            | 关联会话                        |
| `user_id`                 | `bigint`       | NOT NULL            | 所属用户                        |
| `status`                  | `varchar(32)`  | NOT NULL            | `SUCCESS` / `FAILED`        |
| `event_count`             | `int`          | NOT NULL, DEFAULT 0 | 事件条数                        |
| `duration_ms`             | `bigint`       | NULL                | 整轮耗时（毫秒）                    |
| `error_message`           | `text`         | NULL                | 失败时的错误摘要                    |
| `trace_json`              | `json`         | NOT NULL            | 完整 Trace 事件数组               |
| `created_at`              | `datetime`     | NOT NULL            | 创建时间                        |
| `updated_at`              | `datetime`     | NOT NULL            | 更新时间                        |
| `expected_intent`         | `varchar(64)`  | NULL                | 人工标注：期望意图                   |
| `expected_slots`          | `json`         | NULL                | 人工标注：期望槽位（`SlotBundle` 结构）  |
| `expected_clarify_action` | `varchar(32)`  | NULL                | 人工标注：期望澄清动作 `ASK` / `READY` |
| `labeled_by`              | `bigint`       | NULL                | 标注人 user_id                 |
| `labeled_at`              | `datetime`     | NULL                | 标注时间                        |
| `label_note`              | `varchar(512)` | NULL                | 标注备注                        |

**trace_json 顶层结构：**
```json
{
  "traceId": "trace_xxx",
  "sessionId": "sess_xxx",
  "userId": 1,
  "status": "SUCCESS",
  "durationMs": 3200,
  "events": [
    {
      "stepOrder": 1,
      "eventType": "REQUEST_RECEIVED",
      "phase": "HTTP",
      "agentName": null,
      "modelName": null,
      "inputPayload": "{...}",
      "outputPayload": null,
      "latencyMs": null,
      "inputTokens": null,
      "outputTokens": null,
      "totalTokens": null,
      "errorMessage": null,
      "createdAt": "2026-07-01T12:00:00"
    },
    {
      "stepOrder": 2,
      "eventType": "AGENT_CALL",
      "phase": "AGENT",
      "agentName": "IntentAgent",
      "modelName": "qwen-max",
      "inputPayload": "...",
      "outputPayload": "...",
      "latencyMs": 850,
      "inputTokens": 1200,
      "outputTokens": 80,
      "totalTokens": 1280,
      "errorMessage": null,
      "createdAt": "2026-07-01T12:00:01"
    }
  ]
}
```

**常见 eventType：**

| eventType          | phase     | 说明              |
| ------------------ | --------- | --------------- |
| `REQUEST_RECEIVED` | HTTP      | 收到 chat 请求      |
| `INTENT_DECISION`  | INTENT    | 意图识别结果          |
| `CLARIFY_DECISION` | CLARIFY   | 澄清节点决策          |
| `MEAL_SEARCH`      | RECOMMEND | 餐食检索            |
| `MEAL_RANK`        | RECOMMEND | 排序结果            |
| `AGENT_CALL`       | AGENT     | 单次 LLM Agent 调用 |
| `REQUEST_FINISHED` | HTTP      | 请求结束            |

**标注字段用途：**
评估服务（`EvaluationService`）将 `expected_*` 与 `trace_json.events` 中实际输出对比，计算意图准确率、槽位 F1、澄清准确率等指标。未标注记录可通过 `onlyUnlabeled=true` 筛选。

**读写方：**
- 写入：`AgentTraceService`（`openTrace` → 记录事件 → `close` 时 INSERT）
- 标注：`AgentTraceService.updateLabel`
- 读取：`AgentTraceController` 调试 API、`EvaluationService` 批量评估

### 3.4 diet_slot_option — 槽位选项字典表

维护 7 维槽位的合法中文选项，供前端下拉、Clarify 追问和 LLM 输出校验。

| 字段             | 类型            | 约束                  | 说明                        |
| -------------- | ------------- | ------------------- | ------------------------- |
| `id`           | `bigint`      | PK, AUTO_INCREMENT  | 自增主键                      |
| `slot_name`    | `varchar(64)` | NOT NULL            | 槽位英文名，与 `SlotBundle` 字段对应 |
| `option_value` | `varchar(64)` | NOT NULL            | 选项中文展示值                   |
| `sort_order`   | `int`         | NOT NULL, DEFAULT 0 | 同槽位内排序，越小越靠前              |
| `enabled`      | `tinyint`     | NOT NULL, DEFAULT 1 | 1=启用，0=禁用                 |
| `created_at`   | `datetime`    | NOT NULL            | 创建时间                      |
| `updated_at`   | `datetime`    | NOT NULL            | 更新时间                      |
**读写方：**
- 读取：`SlotOptionService` → `SlotOptionMapper.findEnabledValues` / `findSlotNames`
- 写入：运维/后台直接改表或扩展 INSERT，应用层无 CRUD API

### 3.5 meal_item — 餐食条目表

双数据源餐食库：`PUBLIC` 为公共示范菜单，`PERSONAL` 为用户私有菜单。

| 字段              | 类型             | 约束                 | 说明                               |
| --------------- | -------------- | ------------------ | -------------------------------- |
| `id`            | `bigint`       | PK, AUTO_INCREMENT | 餐食 ID                            |
| `source_type`   | `varchar(16)`  | NOT NULL           | `PUBLIC` / `PERSONAL`            |
| `owner_user_id` | `bigint`       | NULL               | `PERSONAL` 时必填；`PUBLIC` 必须为 NULL |
| `name`          | `varchar(128)` | NOT NULL           | 餐食名称                             |
| `meal_time`     | `json`         | NOT NULL           | 适用餐段标签数组                         |
| `mood`          | `json`         | NOT NULL           | 适用心情标签数组                         |
| `scene`         | `json`         | NOT NULL           | 适用场景标签数组                         |
| `health_goal`   | `json`         | NOT NULL           | 健康目标标签数组                         |
| `cuisine`       | `json`         | NOT NULL           | 菜系标签数组                           |
| `taste`         | `json`         | NOT NULL           | 口味标签数组                           |
| `convenience`   | `json`         | NOT NULL           | 便利性标签数组                          |
| `created_at`    | `datetime`     | NOT NULL           | 创建时间                             |
| `updated_at`    | `datetime`     | NOT NULL           | 更新时间                             |
**7 维 JSON 列示例（番茄鸡蛋面）：**
```json
{
  "meal_time": ["午餐", "晚餐", "三餐"],
  "mood": ["疲惫", "低落"],
  "scene": ["工作", "校园", "家里"],
  "health_goal": ["清淡", "养胃", "易消化"],
  "cuisine": ["家常", "粉面"],
  "taste": ["清淡", "番茄味"],
  "convenience": ["快速", "一人食"]
}
```

标签值必须来自 `diet_slot_option` 对应槽位的 `option_value`，否则 `JSON_OVERLAPS` 检索无法命中。

**数据源隔离规则：**

| source_type | owner_user_id | 可见范围                |
| ----------- | ------------- | ------------------- |
| `PUBLIC`    | NULL          | 所有用户的 PUBLIC 模式会话   |
| `PERSONAL`  | 用户 ID         | 仅该用户的 PERSONAL 模式会话 |

**读写方：**
- 写入：`MealService`（个人餐食 CRUD）
- 读取：`MealSearchService` 检索 + `MealRankService` 排序

### 3.6 recommend_feedback — 推荐反馈表

记录用户对推荐结果的显式反馈，供评估报告中的「用户满意度」维度使用。

| 字段           | 类型             | 约束                 | 说明                        |
| ------------ | -------------- | ------------------ | ------------------------- |
| `id`         | `bigint`       | PK, AUTO_INCREMENT | 自增主键                      |
| `user_id`    | `bigint`       | NOT NULL           | 反馈用户                      |
| `session_id` | `varchar(64)`  | NOT NULL           | 关联会话                      |
| `item_id`    | `bigint`       | NULL               | 关联 `meal_item.id`，整轮反馈可为空 |
| `action`     | `varchar(32)`  | NOT NULL           | 反馈动作，见下表                  |
| `rating`     | `int`          | NULL               | 1–5 星评分，可选                |
| `reason`     | `varchar(512)` | NULL               | 文字原因                      |
| `created_at` | `datetime`     | NOT NULL           | 反馈时间                      |

**action 常见取值（评估归一化逻辑）：**

| action（大小写不敏感）                  | 满意度得分 |
| ------------------------------- | ----- |
| `LIKE`, `UP`, `ADOPT`, `ACCEPT` | 1.0   |
| `DISLIKE`, `DOWN`, `REJECT`     | 0.0   |
| 其他                              | 0.5   |

若同时提供 `rating`，优先使用 `rating` 归一化到 0–1（`rating / 5.0`）。
**读写方：**
- 写入：`FeedbackService.save` → `POST /feedback`
- 读取：`EvaluationService` 按 session 列表 + 时间范围聚合

## 4. 数据流与表协作
![[Pasted image 20260820231151.png]]

**一轮 chat 典型落库：**
1. `diet_sessions` — UPDATE 1 行（phase / slots / last_recommendations）
2. `diet_messages` — INSERT 2 行（user + assistant）
3. `diet_request_trace` — INSERT 1 行（整轮 Trace）
