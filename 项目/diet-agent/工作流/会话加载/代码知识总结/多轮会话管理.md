## 1. 多轮场景举例

| 轮次 | 用户说 | 系统需要记住 |
|---|---|---|
| 1 | 「工作很忙，推荐快速的」 | `scene=工作`，`convenience=快速` |
| 2 | 「午餐」 | `mealTime=午餐`（合并上轮 scene/convenience） |
| 3 | 「换一批」 | 排除上轮 3 个 mealId，保留槽位 |

没有会话状态，每轮都是「冷启动」，无法实现澄清补全、换一批、上下文调整。

## 2. SessionState 核心模型

```java
SessionState {
    sessionId,
    userId,
    phase,                // START | CLARIFY | RECOMMEND | PLAN
    sourceMode,           // PERSONAL | PUBLIC
    currentIntent,        // 当前/上一轮确认意图
    slots,                // SlotBundle 7维累积槽位
    lastRecommendations   // 已推荐 mealId 列表（累积）
}
```
持久化表：`diet_sessions`
- `phase` 独立列，便于排查会话卡在哪个阶段
- `slots` JSON 列（含 `_meta.sourceMode` / `_meta.currentIntent`）
- `last_recommendations` JSON 数组列

## 3. 会话生命周期

```
POST /chat (sessionId=null)
    → SessionStateService.create() → 新 sess_xxx

POST /chat (sessionId=已有)
    → loadOrCreate() → 从 DB 恢复 slots/phase/lastRecommendations

每轮结束
    → sessionStateService.save()
    → sessionService.appendMessage() → diet_messages
```
消息表 `diet_messages` 记录每轮 user/assistant 原文 + intent + traceId，供 IntentAgent 拉取 `recentConversationTurns(sessionId, 3)`。

## 4. 槽位增量合并：SlotMergeService
```
choose(history, current):
    current 非空 → 用 current
    current 空   → 保留 history
```
7 维各自独立合并。设计意图：
- 用户第二轮只补「午餐」，不丢失第一轮的「快速/工作」
- 本轮 IntentAgent 未识别到的维度不会被清空
Trace：`SLOTS_MERGED`（stateSlots + intentSlots → mergedSlots）

## 5. 换一批：lastRecommendations 累积排除
### 5.1 写入

`completeRecommendation` 在推荐成功之后:
```java
List<Long> lastIds = recommenda.recommendations().stream().map(option -> option.itemId()).toList();
SessionState savedState = state.appendLastRecommendations(lastIds);
```
`appendLastRecommendations` 使用 `LinkedHashSet` **累积去重，保留插入顺序。**

### 5.2 读取与使用

`handleAdjust` （MEAL_ADJUST 路由）：
```java
List<Long> excludeMealIds = state.lastRecommendations();
return completeRecommendation(..., excludeMealIds);
```
`MealRankService.rank` 过滤 excludeIds，新推荐不会包含已推荐过的 ID。

### 5.3 IntentRevise 保护

无 `lastRecommendations` 时，MEAL_ADJUST 降级为 MEAL_RECOMMENDATION——避免「换一批」误触 但无历史可排除。

Trace：`ADJUST_CONTEXT_RESOLVED` （mergedSlots + excludeMealIds）
评估指标：`multiTurnConsistency`（新推荐是否命中 excludeIds）

## 6.并发安全：会话级锁

```java
Object lock = sessionLocks.computeIfAbsent(sessionId, key -> new Object());
synchronized (lock) {
    ChatResponse response = handleTurn(...);
}
```

同一 sessionId 并发请求串行执行，避免：
+ 两轮同时 merge slots 互相覆盖
+ lastRecommendations 竞态丢失
