## 1. 槽位模型

系统采用 **7 维标准槽位（SlotBundle）**，与餐食标签体系一一对应：

| 槽位字段        | 含义   | 示例标签            |
| ----------- | ---- | --------------- |
| mealTime    | 餐次   | 早餐、午餐、晚餐、三餐...  |
| mood        | 心情   | 疲惫、烦躁、开心、没胃口... |
| scene       | 场景   | 工作、校园、加班、聚餐...  |
| healthGoal  | 健康诉求 | 减脂、清淡、养胃、高蛋白... |
| cuisine     | 菜系   | 川菜、轻食、粉面、粥汤...  |
| taste       | 口味   | 清淡、辣、麻辣、咸鲜...   |
| convenience | 便捷需求 | 快速、一人食、外带方便...  |

合法标签全部存储在 `diet_slot_option` 表，通过：
```
SlotOptionService.findAllOptions()
```

> LLM 只能从字典中选择，不能创造新标签。

## 2. 槽位抽取链路

```
IntentAgent 输出 slots JSON
        |
        v
SlotJsonPicker.pick()
（逐字段过滤非法值，支持多值分隔）
        |
        v
SlotBundle
（本轮槽位）
        |
        v
SlotMergeService.merge(history, current)
（多轮累积）
        |
        v
SessionState.slots
（持久化到 diet_sessions）
```

### 2.1 IntentAgent 内抽取

`IntentAgentService.buildUserPrompt()` 将 `slotOptions` 字典传入 Prompt，要求：
- 语义归一（午饭 -> 午餐、减肥 -> 减脂）
- 无合法候选则输出 `null`，不创造标签。
- 支持单字段多值（逗号 / 顿号分隔）

`parseSlots()` 通 过 `SlotJsonPicker` 对 7 个字段逐一提取。

### 2.2 SlotJsonPicker：结构化校验

```java
// 支持 array 或 string 两种 JSON 格式
// 多值分隔符：, 、 ;
// 只保留 allowed 字典内的值，去重
```
这是槽位抽取的**硬约束层**， 即使 LLM 幻觉输出非法标签，也会被过滤。

### 2.3 SlotMergeService：多轮累积策略

```java
merge(history, current):
    每个维度：
        current 非空 -> 使用 current
        current 空 -> 保留 history
```

设计意图： 用户多轮补充信息时增量累积，本轮未提及的维度不被清空。

## 3. 槽位字典管理

### 3.1 数据来源

+ 数据表：`diet_slot_option`（slot_name、option_value、sort_order、enabled）
+ 预置约 93 条标签（7 维 × 各候选值）
+ 接口：`GET /api/v1/diet/slot-options` 供前端餐食录入表单使用

### 3.2 校验入口

+ **Intent 抽取后**：`SlotJsonPicker` 静默过滤
+ **个人餐食**：`SlotOptionService.validate()` 严格校验，非法标签抛 `DietException`

## 4. 澄清规则与槽位完整性

`ClarifyRuleService.missingSlots()` 定义推荐所需\[**最低槽位**\]：

| 规则              | 说明                                                                        |
| --------------- | ------------------------------------------------------------------------- |
| mealTime 必填     | 未识别餐次 -> 必须追问                                                             |
| healthGoal 条件必填 | 无 healthGoal 且无强偏好（cuisine/taste/scene/convenience 任一非空） -> 追问 healthGoal |

这与 IntentAgent 的 CLARIFY_NEEDED 意图形成 **双保险**：意图层和信息完整性层分别判断。

## 5. 槽位在推荐链路中的使用

| 阶段                     | 使用方式                                                |
| ---------------------- | --------------------------------------------------- |
| MealSearch             | MySQL `JSON_OVERLAPS` 按 7 维标签召回（任一有交集即可命中，空维度不参与过滤） |
| MealRank               | 7 维 overlap 比例求平均，按 matchScore 降序取 Top10            |
| RecommendResponseAgent | 作为 prompt 输入，生成贴合槽位的推荐理由                            |
| RiskGuard              | healthGoal 包含减脂/低糖/控碳水/养胃时触发免责声明                    |

## 6. 持久化

槽位存储在 `diet_sessions.slots` JSON 列，结构：
```json
{
  "mealTime": ["午餐"],
  "mood": ["疲惫"],
  "scene": ["工作"],
  "healthGoal": ["清淡"],
  "cuisine": [],
  "taste": [],
  "convenience": ["快速"],
  "_meta": {
    "sourceMode": "PUBLIC",
    "currentIntent": "MEAL_RECOMMENDATION"
  }
}
```

`_meta` 由 `SessionStateService` 维护，与 7 维槽位同列存储。
