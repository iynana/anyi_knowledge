普通agent.log文件只能记录交互流程；普通业务日志主要回答“接口有没有成功、哪里报错、耗时多少”
但是这个项目包含意图识别、槽位更新、检索重排和推荐生成，我需要结构化的执行链路，从而知道某个结果是由哪些上游输入和决策产生的。

+ 解决多 Agent 链路的因果定位问题
+ 多轮问题的定位方便
+ Trace 可以直接变成离线评估样本

当前项目实际支持两类“回放”：

第一类是**链路查看回放**。可以按 `traceId` 查看单轮完整事件，也可以按 `sessionId` 查询多轮 Trace，还原用户输入、模型调用、中间决策和最终响应。这是只读复盘，不会再次调用模型，也不会重复写会话状态。

第二类是**评估回放**。系统重新解析已经保存的 `trace_json`，提取最终意图、合并槽位、澄清动作、重排候选和返回卡片，再结合人工标注重新计算指标。它可以验证“当时的结果是否正确”，但仍然不是重新执行整条业务链路。
