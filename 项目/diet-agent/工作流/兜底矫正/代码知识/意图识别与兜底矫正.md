## 1.意图体系

系统定义 6 类意图（`Intent` 枚举），作为 Orchestrator 状态机路由的唯一依据：

| 意图                  | 含义      | 典型用户说法            |
| ------------------- | ------- | ----------------- |
| CLARIFY_NEEDED      | 信息不足需追问 | 「帮我推荐一下」（无餐次/目标）  |
| MEAL_ADJUST         | 调整上轮推荐  | 「换一批」「清淡点」「不要太油」  |
| MEAL_RECOMMENDATION | 餐食推荐    | 「中午吃什么」「推荐清淡的」    |
| MEAL_PLAN           | 多餐规划    | 「规划早中晚三餐」「一周清淡饮食」 |
| HEALTH_RISK         | 健康/医疗风险 | 「胃疼吃什么能治好」「绝食减肥」  |
| OTHER               | 与饮食无关   | 「你是 AI 吗」「推荐电影」   |

## 2. 意图识别主链路

```
用户输入
   │
   ▼
IntentAgentService.recognize()
   ├── 加载 slotOptions（DB 槽位字典）
   ├── 注入：userId / sessionId / recentHistory(3轮) / knownSlots / slotOptions
   ├── IntentAgent（qwen-turbo）→ JSON { intent, slots, confidence }
   └── parseResult() 解析 + 字典校验
   │
   ▼
IntentReviseService.revise()  ← 规则二次矫正
   │
   ▼
Orchestrator switch(intent) 路由
```

==「不能完全依靠 agent 的意图识别，在进入推荐之前，规则层面上也需要判断是否有足够的信息」==

### 2.1 IntentAgent 输入上下文

Prompt 要求 Agent 只对「当前这一句」分类，但会附带：

- **recentHistory**：最近 3 轮对话摘要（用于识别「换一批」等上下文相关调整）
- **knownSlots**：会话历史槽位
- **slotOptions**：DB 合法标签字典（约束槽位输出）

### 2.2 Prompt 关键判别规则（intent.txt）

- 最近 3 轮 assistant 已推荐过餐食 + 当前句含「换一批/不太想吃」→ **必须 MEAL_ADJUST**
- 未提到餐次和健康诉求 → **CLARIFY_NEEDED**
- 含「三餐/早中晚/一周饮食」→ **MEAL_PLAN**
- 医疗诊断/极端节食/特殊人群 → **HEALTH_RISK**


## 3. 三层规则兜底
### 3.1 第一层：IntentAgent 解析兜底

`IntentAgentService.parseIntent()`：
+ `intent` 字段缺失或非法枚举 → 走 `fallbackIntent()` 关键词规则
+ LLM 整体异常（超时/JSON 解析失败）→ fallback() 返回低置信度结果（confidence=0.2）
**关键词 fallback 优先级（fallbackIntent）**：
1. 空输入 → CLARIFY_NEEDED
2. 健康风险词（胃疼、糖尿病、孕妇、治好、绝食…）→ HEALTH_RISK
3. 调整词（换一批、清淡点、便宜点…）→ MEAL_ADJUST
4. 规划词（三餐、早中晚、一周）→ MEAL_PLAN
5. 闲聊词（你是谁、你好）→ OTHER
6. 推荐词（吃什么、推荐、晚饭…）→ MEAL_RECOMMENDATION
7. 默认 → CLARIFY_NEEDED

### 3.2 第二层：IntentReviseService 状态感知矫正

LLM 输出后、路由前，`IntentReviseService.revise()` 结合 `SessionState` 做二次修正：

| 规则        | 条件                                            | 矫正结果                                |
| --------- | --------------------------------------------- | ----------------------------------- |
| 健康风险优先    | intent=HEALTH_RISK 或用户输入含健康风险关键词              | 强制 HEALTH_RISK，即使 LLM 置信度较低也走保守风险链路 |
| 无历史推荐不可调整 | intent=MEAL_ADJUST 且 lastRecommendations 为空   | 降级为 MEAL_RECOMMENDATION             |
| 低置信度不进推荐  | intent=MEAL_RECOMMENDATION 且 confidence < 0.4 | 降级为 CLARIFY_NEEDED                  |

健康风险关键词比 IntentAgent fallback 更全（含儿童、高血压、诊断、处方、一天不吃等）。

### 3.3 第三层：Orchestrator 路由层兜底

+ PERSONAL 空库：无个人餐食时直接返回引导文案，跳过意图识别后的推荐链
+ HEALTH_RISK 分支：不走推荐，返回 RiskGuardService.conservativeMessage()
+ OTHER 分支：固定引导文案，不调用 
+ LLM推荐链路内 ClarifyRule：即使 LLM 判 MEAL_RECOMMENDATION，规则层仍可能 ASK 

## 4. 置信度机制

- IntentAgent 输出 `confidence`（默认 0.5）
- `< 0.4` 时 IntentRevise 将 MEAL_RECOMMENDATION 降级为 CLARIFY_NEEDED
- LLM 超时/JSON 解析时 confidence 固定 **0.2**，触发低置信度降级或澄清

## 5. Trace 可观测点

意图相关 Trace 事件：
- `INTENT_RECOGNIZED`：IntentAgent 原始输出
- `INTENT_REVISED`：规则矫正后最终 intent
- `ROUTE_SELECTED`：路由目标

便于对比 LLM 原始判断 vs 规则矫正 vs 最终路由，支撑评估中的 intentAccuracy 指标。
