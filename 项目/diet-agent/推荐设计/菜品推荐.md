## 第一层：MealSearchService

**职责**：按 `sourceMode + userId + slots` 从 DB 召回「至少有一个标签维度有交集」的候选。
- 基于 ==`MySQL JSON_OVERLAPS`== ，判断两个 json 数组是否有共同元素
- 上限 `SEARCH_LIMIT = 50`
- **设计取向：多召回，不在 DB 层做精细排序**

## 第二层：MealRankService

**职责**：在候选集内按「用户需求满足度」二次打分排序。
核心算法（`slotScore`）：
- 7 个槽位维度各自计算 `overlap = 命中标签数 / 用户该维标签数`，求平均后，降序取 Top10
- 过滤 `excludeMealIds`（MEAL_ADJUST 换一批场景）

## 第三层：RecommendResponseAgentService

**职责**：一次 LLM 调用同时产出：
+ `top3` 的多样性重排 `MMR` 推荐
- `recommendations[]`：每项 `{ mealId, reason }`
- `speechText`：面向用户的口语回复

**防幻觉约束**：
1. Prompt 明确要求「不要编造候选之外的餐食」
2. `parseOptions()` 只采纳 `topMeals` 白名单内的 mealId
3. reason 为空的不采纳；缺失 reason 用 `templateReason()` 兜底
4. LLM 失败时用 `templateOptions()` + `templateSpeech()` 全模板兜底


```text
MMR分数 = λ × 用户需求匹配分 - (1-λ) × 与已选餐食的最大相似度, λ = 0.75
```
**选择过程**：
1. 第一项直接选择相关性得分最高的餐食；
2. 后续餐食同时考虑原始匹配分和与已选餐食的相似程度；
3. 基于菜系、口味、健康目标、便捷性等槽位的加权Jaccard计算菜品相似度；
4. 最终选出3个匹配用户需求、同时尽量避免同质化的餐食。

例如原始Top3为：
```text
香煎鸡胸肉
水煮鸡胸肉
鸡胸肉沙拉
```

经过MMR后可能调整为：
```text
香煎鸡胸肉
清蒸鲈鱼
虾仁西兰花
```
