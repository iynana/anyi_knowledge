## 1 倒排索引（Inverted Index）—— 检索的“字典目录”

倒排索引是一种**数据存储结构**，目的是让关键词到文档的映射更快，类似字典的“拼音索引”：
- **正排索引**：文档 → 包含的关键词（比如 `文档1 → [Java, 召回率, 计算]`），查询时要遍历所有文档，速度慢。
- **倒排索引**：关键词 → 包含该词的文档列表（比如 `召回率 → [文档1, 文档3, 文档5]`），查询时直接通过关键词找到对应文档，无需全量遍历。

## 2 BM25（Best Matching 25）—— 相关性的“打分规则”

BM25 是一种**关键词检索的评分算法**
核心作用是：==**对倒排索引找到的候选文档，计算它和用户查询的相关性得分，得分越高越相关**==
它的评分逻辑基于 3 个核心因素（以 Java 代码 RAG 为例）：
1. **词频（TF）**：关键词在文档中出现的次数。比如 `calculateRecall` 在 `code_001` 中出现 2 次，比只出现 1 次的文档得分高。
2. **文档长度惩罚**：避免长文档占优势。比如一个 1000 行的代码文件和一个 50 行的工具类，同样包含 `召回率`，BM25 会给短文档更高的权重（因为关键词密度更高）。
3. **逆文档频率（IDF）**：关键词的稀缺性。比如 `Java` 这个词在所有代码文档中都出现，IDF 低，得分贡献小；而 `calculateRecall` 只在少数文档出现，IDF 高，得分贡献大。
