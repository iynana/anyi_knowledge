消息格式统一用 **JSON-RPC 2.0**，传输方式支持 **stdio**（本地子进程通信） 和 **Streamable HTTP**（远程 HTTP 连接）两种，早期的 SSE 传输已被弃用。

+ **STDIO**： MCP Client（比如 Claude Desktop）在启动时，把 MCP Server 当作一个==子进程==启动，然后通过进程的标准输入（stdin）发送请求、从标准输出（stdout）读取响应。两个进程在同一台机器上运行，通过操作系统的==管道通信==。
	1. 延迟极低：数据直接在操作系统管道里流转，比网络通信快
	2. 安全性好：没有网络安全问题，不担心外部访问
	3. 自动管理：随 Client 启动而启动、随 Client 关闭而关闭，不需要你手动去管进程。

+ **Streamable HTTP**：远程场景下，Server 作为独立的 HTTP 服务运行，Client 通过网络连接访问。Client 通过 POST 请求发送 JSON-RPC 消息，Server 可以选择两种方式返回：  1. 如果是简单的同步操作，直接返回一个普通的 JSON 响应就行；2. 如果是需要流式输出的操作，Server 返回一个 SSE 流，持续推送数据。
	1. Server 可以部署在云端，多个 Client 共享同一个 Server
	2. 有网络延迟，同时需要解决认证问题、网络中断重连
