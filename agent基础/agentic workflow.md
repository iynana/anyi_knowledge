纯 agent 系统：可控性差、成本无法预估、出现问题难以排查处理。
纯 workflow 系统：无法理解多样化的情景或语境，因此也有局限性。

agentic workflow中整体流转、步骤顺序、核心分支、系统交互 是workflow，具体某个节点的任务包括意图识别、查询重写、语义理解、灵活交互是agent能力。
- 骨架 = 固定 Workflow（可控、可运维、可排查）
- 血肉 = 局部 Agent 能力（LLM 推理、动态决策）

比如这样一个完整业务链路
- 用户提问→ 意图分类→ 分支路由（订单问题 / 售后问题 / 账号问题）→ 查业务数据（订单、会员、权限）→ 检索→ 答案组装输出
整体定死的框架是workflow。
中间具体节点是能力是agent：
- 意图分类
	- 流程固定：关键词匹配、正则、固定词库，死板容易漏
	- agent：由 LLM 自主语义推理，理解口语化、歧义、多意图，动态判断用户真实诉求

- 检索
	- 流程固定：必须检索知识库
	- agent：检索哪些知识库？是否需要多轮补充检索、改写查询

- 业务结果 + 规则文档 融合生成回答
	- 流程固定：必须拼接订单数据 + 平台规则
	- agent：结合用户上下文做个性化回答；哪些信息省略、哪些重点强调

- 异常兜底、需求补充
	- 流程固定：只会报错 / 固定话术
	- agent：问题信息不全，主动反问用户补充信息，动态调整后续流程走向
