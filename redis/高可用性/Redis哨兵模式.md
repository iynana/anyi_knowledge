Redis 提供了哨兵机制来实现主从集群的自动故障恢复
1. **监控**：哨兵会不断的检查 master 和 slave 是否正常工作
2. **自动故障恢复**：如果 master 故障，哨兵会将一个 slave 提升为 master。同时哨兵会去重启 master 尝试让其恢复
3. **通知**：哨兵充当 Redis 客户端的服务发现来源，当集群发生故障转移时，会将最新消息推送给 Redis 客户端，通知的信息包括：主节点信息、从节点信息，Redis 客户端收到信息才能做读写分离

_**哨兵机制具体如何监控 Redis 主从集群？**_
哨兵集群基于心跳机制监测服务状态，每隔1秒向集群的每个实例发送ping命令
- **主观下线**：如果某哨兵节点发现某实例未在规定时间响应，则认为该实例“主观下线”
- **客观下线**：若超过指定数量的quorum哨兵节点都认为该实例“主观下线”，则该实例视为“客观下线”，quorum是可配置的值。
- 哨兵节点既可以监测 master 节点，也可以监测 slave 节点。

_**当 master 宕机后，哨兵如何选举新的 master ？**_
1. 基于Raft算法，超过半数即可成为领头哨兵
2. 从从节点中选出优先级最高的主节点：
	+ 过滤掉断连的
	+ 按优先级高选
	+ 按offset大选
	+ 按ID小选

**脑裂**：主节点和从节点、哨兵不在一个网络，哨兵新推了一个主节点
如何防止脑裂？主节点配置：主库只有在至少有 1 个从库，并且这个从库与主库的复制延迟不超过 10 秒时，才接受写请求。
