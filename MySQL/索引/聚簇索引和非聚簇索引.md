# 聚簇索引

最关键的就是将 ==数据与索引== 存储在一起。对于聚簇索引树来说，他的非叶子节点上存储的是索引字段的值，而他的叶子节点上存储的是这条记录的整行数据。索引和数据在物理上是同一个文件。

**唯一性**：每个表只能有一个聚簇索引（通常是主键）
- 在InnoDB中，聚簇索引指的是按照每张表的主键构建的一种索引方式，它是将表数据按照主键的顺序存储在磁盘上的一种方式。这种索引方式保证了行的物理存储顺序与主键的逻辑顺序相同，因此查找聚簇索引的速度非常快
**默认行为**：在 InnoDB 引擎中，如果未显式定义主键，优先使用第一个非空的唯一索引作为聚集索引，没有主键且无非空唯一索引时，自动生成隐藏的 DB_ROW_ID作为聚集索引

# 非聚簇索引

就是将数据与索引分开存储，非聚簇索引的叶子节点存储的是索引+指向数据行的==指针==（如主键值或物理地址）

**多索引支持**：一个表可以有多个非聚簇索引
- 在InnoDB中，非聚簇索引是指根据非主键字段创建的索引，也就是通常所说的二级索引。它不影响表中数据的物理存储顺序，而是单独创建一张索引表，用于存储索引列和对应行的指针

# InnoDB

**在InnoDB中，主键索引就是聚簇索引，而非主键索引，就是非聚簇索引**
- 对于聚簇索引，非叶子节点上存储的是索引，而叶子节点上存储的是==整行记录==
- 对于非聚簇索引来说，非叶子节点上存储的是索引，而叶子节点上存储的是==索引+主键==
- 所以，通过非聚簇索引的查询，需要进行一次回表（回到主键索引），就是先查到主键ID，再通过ID查询所需字段
