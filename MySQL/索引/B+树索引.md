# 问题背景
1. **InnoDB 存储引擎的每次磁盘 I/O 操作读取或写入的大小是==一页==（16KB）**
2. **B+树的结构下每个节点的大小就是一页（16KB），采用页级别指针相连，局部物理相近，可以预读取**
3. **树的高度 == 每次查询数据时磁盘IO操作的次数**

# B+树与B树
+ 数据存储：
	+ B+树的非叶节点仅存**索引**，叶子节点存**索引+记录（==主键索引：key+所有数据，二级索引：key+主键==）**；B树所有节点都是**索引+记录**
	+ B树的节点存了记录，树高瘦，I/O次数多；B+非叶不存记录，树矮胖，I/O次数少
+ 范围查找：B+树所有叶子节点形成双向链表，支持；B树不支持
+ ==查找稳定性==：B+树数据一定在叶子节点获得，稳定；B树不稳定

为什么不基于平衡树或者二叉树或者红黑树实现？
这些==不适合磁盘I/O==，树高太高、随机IO过多，而B+树能显著降低磁盘访问次数并支持范围查询。
