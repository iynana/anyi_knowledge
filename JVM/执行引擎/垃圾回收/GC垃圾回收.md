Java 的内存回收机制主要依赖 JVM 的垃圾回收器**GC自动完成**，**回收不再被任何引用指向的对象所占用的内存**，从而减少内存泄漏、降低程序员负担。
## 垃圾回收算法
垃圾回收算法有三种，分别是**标记清除、标记整理、复制**。

+ 标记清除算法 优点是垃圾回收速度快，缺点是会产生内存碎片，造成内存浪费和溢出
+ 标记整理算法 优点是不会产生内存碎片，缺点是效率较低，整理涉及到对象的移动较复杂
+ 复制算法 优点是不会产生内存碎片，且较为高效，缺点是占用双倍的内存空间（内存空间开销大）

## 分代垃圾回收GC
在实际的编程语言（如 Java）的虚拟机（JVM）中，并不会单独使用某一种算法，而是采用一种更智能的组合策略——**分代收集算法 (Generational Collection)**。

这种算法基于一个重要的经验假设：**绝大多数对象的生命周期都很短，只有少数对象会存活很长时间。**

基于这个假设，JVM 将堆内存划分为两个主要区域：
- **新生代 (Young Generation)**：用于存放新创建的对象。由于这里的大多数对象很快就会“死亡”，因此非常适合使用**复制算法**，可以高效、快速地回收内存。
- **老年代 (Old Generation)**：用于存放从新生代晋升过来的、存活时间较长的对象。由于这些对象存活率高，使用复制算法会造成大量空间浪费，因此更适合采用**标记-整理**或**标记-清除**算法。

通过这种分而治之的策略，现代垃圾回收器能够根据对象的生命周期特点，在不同区域应用最合适的算法，从而在回收效率、内存利用率和系统响应性之间取得最佳平衡。
