类的生命周期是 Java 虚拟机管理类的核心机制，涵盖从类被加载到内存到最终被卸载的完整过程。

它的整个生命周期将会经历 **加载**、**链接**（验证 、准备、解析）、**初始化**、**使用**、**卸载** 五个阶段

## 1. 加载
通过类的全限定名查找字节码文件，将其二进制数据读入内存，并在方法区生成该类的运行时数据结构（如类元信息、常量池等），同时在堆中创建一个对象作为访问入口。

## 2.链接
链接分为三个子阶段：**验证 → 准备 → 解析**
- **验证**：  
    确保字节码符合JVM规范，防止恶意代码破坏虚拟机。包括：
	- 文件格式验证（魔数、版本号）
	- 语义验证（语法、继承关系、final规则）
	- 符号引用验证（确保后续解析能正确完成）

- **准备**：  
    为类变量（static变量）分配内存并设置初始值（零值）
	- 示例：`static int value = 42;` 在此阶段`value`被初始化为0，而非42（赋值在初始化阶段执行）
	- 若变量是`final static`常量（如`static final int VALUE = 42;`），则直接赋值为42

- **解析**：  
    将==常量池==中的**符号引用**（符号化的类、方法、字段名称）替换为**直接引用**（内存地址或句柄）
	- 例如：将`java.lang.Object`替换为指向方法区中`Object`类元数据的指针

## 3.初始化
执行类构造器`<clinit>()`方法（由编译器自动生成），完成类的静态变量，静态代码块执行初始化操作。

## 4.使用
通过实例化、反射等方式使用类

## 5.卸载
回收类的元数据（方法区）及对应的`Class`对象
需要同时满足以下三个条件：
1. 该类的所有实例已被垃圾回收（堆中无存活对象）。
2. 该类的`Class`对象未被任何地方引用（如反射、静态变量）。
3. 加载该类的`ClassLoader`实例已被回收。
